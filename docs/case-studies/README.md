# Failure case studies

These are recorded harness runs, not marketing transcripts.

Each of the first twelve cases is generated by `scripts/capture_case_studies.py`
against a **scripted model**. That is deliberate: the point is the harness
contract, not how clever a particular 0.8B checkpoint felt on Tuesday. The
script is checked in CI (`--check`) so the logs cannot drift from the code.

Cases 13 and 14 are leftover files from live TDD runs that shipped in
`examples/artifacts/`. They show what verification does *not* save you from.

Reproduce the scripted set:

```bash
python3 scripts/capture_case_studies.py --check
```

## 1. Immediate complete

Small local models often narrate a solution and set `status: complete` on
turn one. An earlier version of this loop would then call
`commit_to_reality()` on an empty or stale VFS.

Now: no passing pytest/unittest, no disk write, rejected JSONL.

```text
[HARNESS INTERVENTION] Refusing unverified completion.
[ABORT] Maximum iterations reached without verified task completion.
[DATASET EXPORT] rejected / unverified trajectory saved to $WORKSPACE/rejected.jsonl (reward=0.0).
```

Full log: [01-unverified-complete.log](logs/01-unverified-complete.log)

## 2. Message count is not success

The old loop had `if "[SIMULATION VERIFIED SUCCESS]" in last_msg or len(messages) > 3`.
Writing two dummy files was enough to unlock a commit.

That branch is gone. After two `write_file` calls the model still cannot
complete.

Full log: [02-message-count-is-not-success.log](logs/02-message-count-is-not-success.log)

## 3. Failed tests

The model wrote a unittest, ran it, saw a failure, and declared victory
because “I ran the tests.”

The sandbox returned `[SIMULATION FAILED]`. `commit_to_reality` stayed
blocked. The failing file never appeared on the host.

Full log: [03-failed-tests-blocked.log](logs/03-failed-tests-blocked.log)

## 4. A successful print is not verification

`run_command("python3 hello.py")` exits 0 and is labelled
`[SIMULATION VERIFIED SUCCESS]` as a *command* result. The loop still
refuses to finish: the last command must be pytest/unittest (or `test_*.py`).

This is the safety story in one log. Generic shell success is not a test.

Full log: [04-print-is-not-verification.log](logs/04-print-is-not-verification.log)

## 5. Path jail

`write_file("../escape.py", ...)` is rejected. The host path does not exist.
Commit is independently blocked because nothing was verified.

Full log: [05-path-jail.log](logs/05-path-jail.log)

## 6. Inference errors are not completion

An earlier client returned `{"status": "complete", "final_answer": "Execution failed."}`
on HTTP errors, which the loop treated as a successful task.

The client now returns `_inference_error: true` with `status: in_progress`.
The loop retries and never commits.

Full log: [06-inference-error.log](logs/06-inference-error.log)

## 7. Surgical edit miss

Local models guess indentation and retry `search_and_replace` forever.
The tool tells them to stop and rewrite the file. Completion is still gated.

Full log: [07-search-and-replace-miss.log](logs/07-search-and-replace-miss.log)

## 8. Escaped newlines

A JSON `write_file` sometimes delivers the whole module as one physical line
containing the two characters `\` and `n`. The tool unescapes that into real
newlines inside the VFS. The host is still unchanged until tests pass.

```text
VFS Updated: str_utils.py
host_exists: False
vfs_repr: 'def is_palindrome(s):\n    return s == s[::-1]\n'
[VFS COMMIT BLOCKED] Refusing to write unverified VFS state to disk.
```

Full log: [08-escaped-newlines.log](logs/08-escaped-newlines.log)

## 9. Zero tests collected

Pytest exit code 5 (`no tests ran`) is a failed simulation. The harness
appends a note to write `def test_...` functions. A file named `test_*.py`
that only `print`s is not a test suite.

Full log: [09-zero-tests-collected.log](logs/09-zero-tests-collected.log)

## 10. Timeout

Commands that exceed the sandbox timeout score 0.0. A hung `sleep` cannot
be laundered into a commit.

Full log: [10-command-timeout.log](logs/10-command-timeout.log)

## 11. Missing tool call

`in_progress` without `tool_call` is rejected (ADR-001). Hitting
`max_iterations` exports a rejected trace rather than a chosen one.

Full log: [11-abort-exports-rejected.log](logs/11-abort-exports-rejected.log)

## 12. Tests that pytest cannot collect

Putting `assert` under `if __name__ == '__main__'` in the implementation
file is a pattern this harness sees constantly. `python3 str_utils.py` might
print `ok`. `python3 -m pytest str_utils.py` collects nothing.

Full log: [12-tests-live-in-implementation.log](logs/12-tests-live-in-implementation.log)

## 13. Live artifact: Stack tests against a list

`examples/artifacts/stack.py` is output from a real TDD prompt. The
implementation class is reasonable. The tests in the same file do this:

```python
def test_push():
    stack = []
    stack.push(1)
```

`list` has no `push`. Pytest would fail. That failure is the product:
those tests must go green in the sandbox before the files land.

See also `examples/artifacts/test_stack.py`, which defines `Stack` inside
the test module and then compares a `Stack` instance to `[1]`.

## 14. Live artifact: money parser with `float`

`examples/artifacts/money.py` came from a checkout-form prompt:

```python
return int(float(text) * 100)
```

```python
>>> int(float("1.15") * 100)
114
```

A suite that only checks `$12.34`, `0.99`, and `10` can pass and still
charge the wrong number of cents. **The verifier is only as good as the
tests the model wrote.** The harness will not invent missing cases.

That is the honest limit of “verification-gated commit.” Use it for tasks
where you can state the spec in pytest. Do not use it as a proof of
correctness.

## What we are not claiming

- These scripted logs are not win-rates on a public agent benchmark.
- A passing local pytest run is not a security boundary (see
  [SECURITY.md](../../SECURITY.md)).
- Swarm search, weight updates, and video world models are still
  [north-star](../NORTH_STAR.md) language.
